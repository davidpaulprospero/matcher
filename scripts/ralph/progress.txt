## Iteration 16 - US-002: Add progressive backoff before cookie rotation
- Focus: rate-limiting
- Status: COMPLETE

### Changes Made
Implemented progressive backoff delay before escalating to cookie rotation on rate limit errors.

**Config additions (src/config/sections/download.py):**
- New `RateLimitConfig` dataclass with:
  - `initial_backoff_seconds: float = 5.0` - Initial delay on first rate limit
  - `max_backoff_before_rotate: float = 60.0` - Max cumulative delay before rotation
  - `backoff_multiplier: float = 2.0` - Exponential growth factor
- Added `rate_limit: RateLimitConfig` field to `DownloadConfig`
- Added `__post_init__` handling for dict-to-dataclass conversion

**Config additions (config.yaml):**
- New `download.rate_limit` section with all three settings
- Documented backoff sequence example in comments

**Core implementation (src/downloader/core.py):**
- Added tracking state: `_rate_limit_backoff_count` and `_rate_limit_total_delay`
- Modified `handle_rate_limit_error()` to apply progressive backoff BEFORE rotation:
  1. On rate limit, calculate delay: `initial_backoff * (multiplier ^ count)`
  2. Cap delay so total doesn't exceed `max_backoff_before_rotate`
  3. Sleep and increment counters
  4. After max delay reached, reset counters and escalate to cookie rotation
- Added `_reset_rate_limit_backoff()` method
- Reset backoff on successful download (after videos found)
- Comprehensive logging of backoff progress (attempt #, delay, total/max)

**Backoff sequence with defaults:**
```
1st rate limit: wait 5s (total: 5s)
2nd rate limit: wait 10s (total: 15s)
3rd rate limit: wait 20s (total: 35s)
4th rate limit: wait 25s (total: 60s) -> rotate cookie
```
